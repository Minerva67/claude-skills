# 拆解报告的结构

这个骨架来自一次真实的双产品拆解实践（Synthesia 后台调研 + Knowlify 三层拆解）。
按需增删章节，但**元信息块、更正块、结构性观察、未覆盖清单**这四件不要省——
它们承担的是可信度，不是内容。

---

## 0. 元信息块（页面顶部，表格形式）

读者要在三秒内知道这份报告能信到什么程度。

| 字段 | 写什么 |
|---|---|
| 调研对象 | 具体到域名和范围（"公开站全站 + 登录后完整后台"） |
| 调研日期 | 绝对日期 |
| **账号状态** | 最关键的一行。档位、额度、余额变化。没账号就明写"无账号，未登录" |
| 方法 | 怎么取的证：逐路由遍历？程序化注入测试？实际提交生成？ |
| **保真度** | 哪几节是实测、哪几节是反推。这是全文的免责声明 |
| 配套文档 | 有对照文档就在这里指出来 |

## 0.5 更正块（如果有前一版）

**只在结论被推翻时出现，但一旦出现就放在最显眼处。**

每条写三段：
- **原结论**（加粗，说人话）
- **为什么错**：当时基于什么推的
- **实际是什么**：新证据 + 具体数字

这块的价值不只是纠错。读者从"营销面和产品面差多远"里能读出这家公司的成熟度和诚信水位。

## 一、功能总览

- **1.1 信息架构**：路由表 / 导航结构。标注每一项是实测还是推断
- **1.2 能力清单**：按"对成交的实际权重"重排，而不是按官网的排列。分成
  「准入门槛」（没有就不能进这个市场）/「差异化」/「可比功能」/「战术功能」
- **1.3 付费边界**：能力 × 档位的矩阵。**最后单独指出最狠的那一行**并解释它的商业设计

## 二、用户旅程地图

- **2.1 情绪曲线**：SVG 折线，横轴阶段、纵轴情绪。标出峰值和谷底，**谷底要区分是体验瑕疵还是商业设计**
- **2.2 路径/管线图**：SVG 流程图。重点画**非主干的箭头**——撞墙后去哪、产出如何回流、哪一步是强制升级门
- **2.3 阶段展开**：每阶段一张表，固定七行：用户目标 / 触点 / 关键动作 / 心里在想 / 摩擦点 / 产品手段 / 变现。
  「心里在想」用第一人称口语，别写成分析腔
- **2.4 决定成败的瞬间**：3–5 个，按对留存的影响排序，每个写「成则 / 败则」
- **2.5 流失风险点**：风险点 / 所在阶段 / 性质（认知负荷、能力天花板、合规风险、规模化断点…）

阶段划分建议沿用同一套（落地 / 起草 / 初稿 / 打磨 / 本地化 / 协作 / 交付 / 规模化），
**跨产品对照时同一套阶段划分是刚需**。

## 三～N、逐模块详解

按产品实际有的面来分节，不要硬套。每节：
- 界面截图（有 L2 就放实测图）
- 选项/参数的**完整枚举**（清单比描述有用）
- 一句"这里真正在做的事"

优先给这些模块独立成节：**核心创作面板、参数/预置系统、产出物质量、付费墙所在页、定价页、增长机制、技术栈证据**。

## 技术栈与供应链

不是猜架构，是列证据：

| 环节 | 证据 | 结论 |
|---|---|---|
| 图像/视频 | 资源托管在 `xxx.media` | 用了某推理平台 |
| 语音 | 音色命名沿用某家的预置名 | 外采 |
| 管线 | 状态机文案序列 | 两段式生成 |

推断标可信度（高/中高/中）。**修正过的技术判断要显式写出来。**

## 结构性观察（报告的心脏）

5–6 条。每条三段式：

- **现象**：客观描述 + 具体证据
- **价值**：这样做的合理性是什么（先站在对方立场理解）
- **看法**：你的判断。**必须有立场**，可以是"这很聪明因为…"也可以是"这很危险因为…"

好的观察长这样：
- 不是"它有 A 功能"，而是"它把 A 锁在最高档，等于把自己拉来的客户全逼向销售流程"
- 不是"它用了外采模型"，而是"两家都不做底模，但押的资产升值曲线相反"

**至少有一条要指出它的战略脆弱点。** 一份只夸不批的拆解没有决策价值。

## 逐项对照（有对标文档时）

一张表，维度选**能暴露取舍**的：产品形态 / 内容真源 / 自研资产 / 底模来源 / 精修能力 / 付费墙切口 / 数据归属 / 客户覆盖 / SEO 起点 / 形态延伸 / 组织形态。

表后写一段「对照后最锋利的一句」——两家最根本的分歧是什么。

## 对自家产品的可行动清单（如果用户有自己的产品）

三档分类，用 pill 标签：
- `直接抄` — 已验证有效、迁移成本低
- `先评估` — 有效但有前提条件，写清条件是什么
- `别抄` — 明确指出为什么不能抄（法务风险、组织不匹配、或**用户自己踩过同样的坑**）

如果用户的产品有已知历史问题（从记忆或对话里得知），**明确把竞品的做法和那个坑关联起来**。

## 附：未覆盖

诚实列出没验到的东西，每条写清**验它需要什么**（"需要一个月 Pro $29"）。
按价值排序，第一条应该是"剩下最值得验的一个未知项"。

---

## 写作调性

- 中文，句子完整，不用缩写和箭头链
- 数字必须具体：不写"很贵"，写"$0.242/credit vs $0.083，差 2.9 倍"
- 引用对方原文时保留英文原句，关键措辞加粗
- 表格放可枚举的事实，解释放在表格外的正文里
- 每节结尾可以有一个 callout 收束判断，但别每节都有——滥用会稀释
